    MycoNote-CLI v0.7.1 audit report¶

    Audit date: 2026-04-25 Auditor: Benjamin Narh-Madey Scope: Verify every claim about the codebase against actual code, fix drift, and add a major expansion of the learn tutorial. Builds on the three rapid feature releases v0.5.0 → v0.7.0.

    The user request, verbatim: "make sure everything works, no errors, and all claims are verified and actually work" and "improve the details and breadth of the learn function." This pass addresses both.

    Tests¶

    Suite Before (v0.7.0) After (v0.7.1) Δ
    cargo test --release --lib 422 passed, 10 ignored 432 passed, 10 ignored +10
    cargo test --release --test unit_tests 56 passed, 1 ignored 56 passed, 1 ignored 0
    cargo test --release --test integration_test 53 passed, 4 ignored 53 passed, 4 ignored 0
    Total 531 541 +10

    Net: +10 lib tests for the new learn lesson catalogue. No new failures were introduced; no pre-existing tests had to be modified.

    cargo fmt -- --check passes clean before and after. cargo build --release produces zero warnings before and after.

    The 10 new lib tests (in src/learn/lessons.rs::tests) cover:

    • catalogue_has_twenty_lessons — guards the count after expansion
    • every_lesson_has_a_title_and_at_least_one_item — non-empty invariant
    • every_lesson_ends_with_a_verification_step — pedagogical contract
    • lesson_titles_are_unique — prevents duplicate titles after refactors
    • rna_seq_track_lessons_present_by_keyword — guards lessons 9-14
    • modern_predictor_lessons_present — guards lessons 15-16 (BRAKER, GeneMark)
    • quality_track_lessons_present — guards lessons 17-20
    • find_lesson_by_name_works_for_new_lessons — name-based lookup integrity
    • lesson_durations_are_reasonable — est_minutes ∈ [5, 20]
    • no_lesson_references_removed_subcommands — guards against re-introduction of myconote-cli phylogeny, myconote-cli place, Y1000+ references in any lesson body.

    Help-text corrections¶

    For each of the 26 subcommands we ran ./target/release/myconote-cli <cmd> --help and cross-checked the listed flags against the parser. Every help call exited 0. No advertised-but-nonexistent flags were detected. No existing-but-unadvertised flags were detected on the surface checks.

    ./target/release/myconote-cli (no args) prints banner + help. ./target/release/myconote-cli --version prints banner with version. ./target/release/myconote-cli totally-not-a-real-command exits with Unknown command: …. Try: sort | mask | train | predict | … | learn (all 26 subcommands listed).

    No help-text drift was found in this release. (The most likely place for drift was prevented by the manual-arg-parsing pattern: each subcommand's inline --help block is in the same file, near the parser, so they co-evolve.)

    External-tool error-path checks¶

    Spot-checked two wrappers with deliberately-bad tool paths:

    1. myconote-cli quant ... --salmon /nonexistent/salmon (with a real input FASTQ and CDS): exits 1 with Error: quant external tool (salmon): running '/nonexistent/salmon --version': No such file or directory (os error 2). Names the tool. ✓
    2. myconote-cli mask /nonexistent/genome.fa --engine repeatmodeler: exits 1 with Error: IO error: No such file or directory (os error 2). The error is correct but generic — it doesn't name the missing FASTA path or the tool family. Recorded as a small UX improvement candidate for v0.7.x; not load-bearing for this release.

    No unwrap() panics or process::exit(0) on failure paths were identified. The Result<()> return on main correctly propagates Err to a non-zero exit via anyhow.

    SIGPIPE: myconote-cli species | head -3 exits cleanly (head's EXIT=0). The binary doesn't panic on broken pipe.

    Things flagged but not fixed¶

    1. Manuscript count drift (15 sources, ~35 species). Left as a TODO block at the top of docs/paper/myconote_manuscript.md. The manuscript prose pre-dates v0.5+ feature work and may need a meaningful re-pass anyway; numerical-only edits would risk breaking prose flow. Code is the source of truth; user decides the framing.
    2. src/cli/commands.rs was dead scaffold. Now deleted. The dead file was a latent drift risk because grep tooling (and humans) would keep re-finding Phylogeny(PhylogenyArgs) in it. Removing it eliminates the false-positive ahead of future audits.
    3. docs/talks/gsa_2026_slides.md references place and Y1000+. Kept as a record of the actual delivered talk. If the user wants a "current capabilities" slide deck for a future talk, that's a separate v0.7.x or v0.8.0 deliverable.
    4. Mask wrapper's "missing input FASTA" error. Generic IO error: No such file or directory (os error 2) instead of naming the file. Not a bug — error path works, exit code is correct — but a UX paper-cut. Logged for v0.7.x.
    5. CI workflow audit. Out of scope this pass per the task brief (billing-broken, not user-affecting). v0.8.0 candidate.
    6. .github/workflows/*.yml deep scan. Same as above.
    7. Live-tool integration tests for new RNA-seq lessons. All the lessons themselves are tested for catalogue presence and content integrity. The actual pipelines (quant, ase) have unit + CI-safe integration tests; live salmon/fastp smoke tests stay gated under #[ignore] per the existing pattern.

    Decisions the user might want to revisit¶

    • Manuscript counts. The "fifteen annotation sources" framing appeared in v0.5.0's manuscript draft and persisted unchanged through v0.7.0. Either reduce to 11 (matches code + README) or rewrite the list to legibly count InterProScan member databases separately (Pfam-via- InterPro, TIGRFAM, SMART, Gene3D, Superfamily) so the 15 is defensible.
    • docs/talks/gsa_2026_slides.md. Kept verbatim as a delivered-talk artifact. If you'd like a v0.7-current slide deck, that's a separate task.
    • The 33+ tools claim. Was 32, never user-facing; if any future doc page wants to assert a count, use the live src/install/mod.rs::Tool count instead of a hard-coded number.
