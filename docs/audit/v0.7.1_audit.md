## Help-text corrections

For each of the 26 subcommands we ran `./target/release/myconote-cli <cmd>
--help` and cross-checked the listed flags against the parser. Every help
call exited 0. No advertised-but-nonexistent flags were detected. No
existing-but-unadvertised flags were detected on the surface checks.

`./target/release/myconote-cli` (no args) prints banner + help.
`./target/release/myconote-cli --version` prints banner with version.
`./target/release/myconote-cli totally-not-a-real-command` exits with
`Unknown command: …. Try: sort | mask | train | predict | … | learn`
(all 26 subcommands listed).

No help-text drift was found in this release. (The most likely place for
drift was prevented by the manual-arg-parsing pattern: each subcommand's
inline `--help` block is in the same file, near the parser, so they
co-evolve.)

## External-tool error-path checks

Spot-checked two wrappers with deliberately-bad tool paths:

1. `myconote-cli quant ... --salmon /nonexistent/salmon` (with a real input
   FASTQ and CDS): exits **1** with
   `Error: quant external tool (salmon): running '/nonexistent/salmon
   --version': No such file or directory (os error 2)`. Names the tool. ✓
2. `myconote-cli mask /nonexistent/genome.fa --engine repeatmodeler`: exits
   **1** with `Error: IO error: No such file or directory (os error 2)`.
   The error is correct but generic — it doesn't name the missing FASTA
   path or the tool family. Recorded as a small UX improvement candidate
   for v0.7.x; not load-bearing for this release.

No `unwrap()` panics or `process::exit(0)` on failure paths were
identified. The `Result<()>` return on `main` correctly propagates `Err`
to a non-zero exit via `anyhow`.

SIGPIPE: `myconote-cli species | head -3` exits cleanly (head's `EXIT=0`).
The binary doesn't panic on broken pipe.

## Things flagged but not fixed

1. **Manuscript count drift (15 sources, ~35 species).** Left as a TODO
   block at the top of `docs/paper/myconote_manuscript.md`. The
   manuscript prose pre-dates v0.5+ feature work and may need a
   meaningful re-pass anyway; numerical-only edits would risk breaking
   prose flow. Code is the source of truth; user decides the framing.
2. **`src/cli/commands.rs` was dead scaffold.** Now deleted. The dead
   file was a *latent* drift risk because grep tooling (and humans) would
   keep re-finding `Phylogeny(PhylogenyArgs)` in it. Removing it
   eliminates the false-positive ahead of future audits.
3. **`docs/talks/gsa_2026_slides.md` references `place` and Y1000+.**
   Kept as a record of the actual delivered talk. If the user wants a
   "current capabilities" slide deck for a future talk, that's a separate
   v0.7.x or v0.8.0 deliverable.
4. **Mask wrapper's "missing input FASTA" error.** Generic `IO error: No
   such file or directory (os error 2)` instead of naming the file. Not a
   bug — error path works, exit code is correct — but a UX paper-cut.
   Logged for v0.7.x.
5. **CI workflow audit.** Out of scope this pass per the task brief
   (billing-broken, not user-affecting). v0.8.0 candidate.
6. **`.github/workflows/*.yml` deep scan.** Same as above.
7. **Live-tool integration tests for new RNA-seq lessons.** All the
   lessons themselves are tested for catalogue presence and content
   integrity. The actual pipelines (`quant`, `ase`) have unit + CI-safe
   integration tests; live `salmon`/`fastp` smoke tests stay gated under
   `#[ignore]` per the existing pattern.
