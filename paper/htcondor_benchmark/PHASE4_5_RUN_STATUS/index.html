    Phase 4–5 execution status — production timing + accuracy matrix¶

    Live reproducibility record for BENCHMARK_PLAN.md §7 Phases 4 (Stage-1 timing) and 5 (production timing + accuracy). Written as the run proceeds; this is manuscript Methods raw material. Last updated: 2026-10-15.

    What this run does and why¶

    Four-tool fungal-annotation benchmark (MycoNote vs funannotate / MAKER / BRAKER) on the full 14-genome panel. Two measurement axes, per §1–§3: - Timing (real HPC-noise variance): Stage-1 n=5, production n=10; analysed on per-genome medians. Wall-time is the headline; CPU-seconds the robustness check. - Accuracy (near-deterministic): 3-rep determinism audit, collapsed to the per-genome mean.

    Fairness: timing-node pinning decision (FLAGGED)¶

    §3 calls for same-node pinning of the 4 tools per genome. On this shared pool strict same-node pinning (Machine == "<one host>") is infeasible: - Only 15 AVX2 hosts exist, heterogeneous (6–102 cores); the pool carries 500–700 idle jobs from other users. - Pinning a genome's whole tool×rep block to one named host serialises ~20–40 jobs onto a single contended machine and stalls BRAKER (16c/64 GB) indefinitely.

    Closest fair alternative adopted (exactly the §-anticipated fallback, "pin to one node class + report CPU-time"): pin all four arms to one microarch generation, x86_64-v3, so wall-time is compared on identical-ISA hardware. - The AVX2 pool splits into x86_64-v3 (9 hosts: scarcity-1,2,3,4,11,12,14,18,19) and x86_64-v4 (6 hosts). v3 chosen: more hosts (throughput, less contention) and more large-memory hosts able to seat BRAKER's 16c/64 GB slot (scarcity-11/12/18/19). - Requirement on every timing sub: requirements = (TARGET.has_avx2 =?= true) && (TARGET.Microarch =?= "x86_64-v3") (matchmaking verified satisfiable: 27 slots match). - CPU-seconds (performance.json total_cpu_seconds, captured by every wrapper via /usr/bin/time -v) is reported alongside wall-time as the co-tenant-contention-robust check. True single-tenant isolation is impossible on a partitionable-slot shared pool regardless of pinning, which is the independent reason CPU-seconds is reported. - Accuracy runs are NOT pinned (deterministic, hardware-independent).
